# 功能设计：赋分制分析与知识点智能录入

> 日期：2026-08-20
> 状态：设计定稿，待实施
> 范围：本轮新增两大能力，涉及后端模型/迁移/服务/API 与前端配置、录入、分析页面

---

## 一、总体目标

1. **赋分制分析**：支持原始分与赋分双轨分析，支持本科/特控/单科/双上线统计；对多校统考（数据完整）与小范围统考（数据缺失）均能自适应分析。
2. **知识点智能录入**：支持通过 Excel 模板、目录文本、AI 抽取三种方式导入教材/课程标准，自动生成知识点树，不再逐点手录。

- `exam_subjects` 无“是否赋分科目”标记
- `ScoringScheme` 模型已存在（brackets 比例区间 JSON），但无迁移、无 API，属死代码 → 本设计将其启用
- 无上线统计能力

### 2.2 数据模型（迁移 005）

**① 启用 `scoring_schemes` 表（赋分方案）**

```python
class ScoringScheme(BaseModel):
    __tablename__ = "scoring_schemes"
    name = Column(String(100), nullable=False)      # 方案名
    description = Column(Text, default="")
    brackets = Column(JSON, nullable=False)         # 等级区间数组
    is_preset = Column(Boolean, default=False)      # 内置方案，不可删除
    sort_order = Column(Float, default=0)
```

`brackets` 结构（按 rank_start 升序）：

```json
[
  {"rank_start": 0.0,  "rank_end": 0.15, "score_start": 100, "score_end": 86},
  {"rank_start": 0.15, "rank_end": 0.50, "score_start": 85,  "score_end": 71},
  {"rank_start": 0.50, "rank_end": 0.85, "score_start": 70,  "score_end": 56},
  {"rank_start": 0.85, "rank_end": 0.98, "score_start": 55,  "score_end": 41},
  {"rank_start": 0.98, "rank_end": 1.0,  "score_start": 40,  "score_end": 30}
]
```

内置方案（种子数据，数值以各省官方文件为准，实施时核对）：
- 新高考 3 分一段（15%/35%/35%/13%/2% → 100–86 … 40–30，湖南/湖北/广东等）
- 浙江 1 分一段（21 档逐档赋分）
- 山东 5 等 8 级（3%/7%/16%/24%/24%/16%/7%/3%）
- 自定义（用户新建）

### 2.3 赋分换算算法（ScoreConversionService）

输入：科目全体考生原始分 + 方案 brackets。输出：每人赋分。

1. 原始分降序排序；对每个唯一分数 x 计算累计百分比 `p(x) = 该分数及以上人数 / 总人数 × 100`
2. 按 p 落入唯一等级 `Bk`（`rank_start×100 ≤ p < rank_end×100`）
3. 段内等比例插值：`赋分 = score_end + (score_start - score_end) × (x - 段内原始分下限) / (段内原始分上限 - 段内原始分下限)`，四舍五入取整；段内只有一个分数时赋分取该段上限
4. 同原始分 → 同 p → 同等级 → 同赋分（并列同分处理）

### 2.4 自动 / 手动换算

- 科目 `conversion_mode=auto`（默认）：成绩导入缺赋分时，导入后按方案自动换算并写 `converted_score`，`converted_source=system`；随时可切换为 manual
- `conversion_mode=manual`：`converted_score` 由用户录入/编辑（导入模板赋分列），系统不再覆盖
- 提供手动触发重算接口（调整方案后一键重算）

### 2.5 分析与上线统计

分析服务新增 `score_mode` 参数：`raw | converted | both | auto`（默认 auto，按数据完整度降级）：

| 完整度 | 典型场景 | 行为 |
|---|---|---|
| 全量 | 市统考：原始分+赋分+分数线 | 双轨分析 + 上线统计（官方线） |
| 半量 | 有原始分+赋分，缺分数线 | 双轨分析 + 参考线统计（标注“参考”） |
| 最小 | 小范围统考只有原始分 | 原始分分析 + 按方案自动换算赋分 + 参考线 |

新增能力：
- **上线统计**：总分 = 语数外原始分 + 选考赋分；按年级/班级统计各线（本科/特控/专科）上线人数、上线率
- **单科线**：任选科目配置单科线，统计单科上线
- **双上线**：总分达线且单科达线的人数与率
- **一分一段表**：总分每 1 分的人数、累计人数（按原始/赋分双口径）

## 三、知识点智能录入

### 3.1 现状与问题

- `subject_knowledge_points` 已支持树形（parent_id），`KnowledgePoints.vue` 仅支持逐点手录
- `seed_knowledge.py` 每次启动**清空重建**，会覆盖用户数据 → 必须改造
- 已有 LLM 接入（AIChatService，OpenAI 兼容），可复用做 AI 抽取

### 3.2 数据模型（迁移 005 续）

    __tablename__ = "knowledge_sources"

```python

```

**③ seed 改造**：预设库改为“空库时填充”，且仅清理 `origin=preset` 数据，绝不触碰用户数据

### 3.3 三级导入管线（A/B/C 本期全部实现）

统一流程：`上传/粘贴 → 文本抽取 → 层级识别 → 标准化 JSON → 树形预览确认 → 事务入库`

| 模式 | 输入 | 识别原理 | 备注 |
|---|---|---|---|
| A 模板 | Excel（列=层级：学段/册/单元/课/节/知识点） | 列即层级，直接建树 | 零 AI，最可控 |
| B 文本规则 | 教材/课标目录文本 | 编号模式正则识别层级 | 零 AI，快 |
| C AI 抽取 | Word/PDF/文本 | LLM 抽取层级 JSON | 最省力，需配置 LLM |

- 文本抽取：Word（python-docx）、Excel（openpyxl）已具备；PDF 新增 `pypdf`，先取文本层，无文本层走 OCR 适配器
- 预览：前端树形展示，支持勾选范围、改名、调整层级、显示“疑似重复”，确认后才落库
- 入库：按 (subject_id, name) 同名合并（父同名→合并并追加子节点；叶子同名→合并或标记疑似重复由用户勾选）

### 3.4 层级识别规则引擎（模式 B）

编号模式优先级匹配（正则）：
- 中文序号：`一、二、…`（第一层）
- 数字层级：`1.`、`1.1`、`1.1.1`（第二/三/四层）
- 括号序号：`(1)`、`（1）`、`①②③`（次一层）
- 章节词：`第一章`、`第1课`、`Unit 1`、`Module 1`
- 同级缩进/编号连续变化决定 parent；无法判定的行并入上一层作为描述

### 3.5 AI 抽取约束（模式 C）

- 文本分块（按章节，每块约 6000 字）送入 LLM
- 强制 JSON Schema 输出：`{"items":[{"name":"…","level":1,"children":[{"name":"…","level":2}]}]}`
- 校验失败自动重试 1 次，再失败回退模式 B 规则解析
- 未配置 LLM 时前端禁用模式 C 并提示
- 输出与规则引擎结果合并（规则为主，AI 补全精修）

### 3.6 OCR 预留

- 定义 `KnowledgeOcrAdapter` 抽象接口：`extract_text(pdf_bytes) -> str`，本期提供空实现（返回 None 并提示“扫描版暂不支持”）
- 配置项 `OCR_PROVIDER=none`，后续可切换 PaddleOCR / Tesseract 等，无需改动管线

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /knowledge-points/import/template.xlsx | 下载模式 A 模板 |
| POST | /knowledge-points/import/excel | 模式 A：Excel 导入 → 预览数据 |
| POST | /knowledge-points/import/text | 模式 B：目录文本 → 预览数据 |
| POST | /knowledge-points/import/ai | 模式 C：文档 AI 抽取 → 预览数据 |
| POST | /knowledge-points/import/preview | 提交预览确认结果（含合并选项）→ 事务入库 |

## 六、风险与依赖

1. **alembic 迁移链当前已损坏**：工作区删除了 `b7dee85ed6bc_initial_migration.py`，导致 002→初始迁移 断链。实施前必须先修复迁移链（恢复或重建初始迁移）。

3. **LLM 依赖**：模式 C 依赖 LLM 配置（`.env` 的 LLM_*）；未配置时功能降级为 A/B。
4. **PDF 扫描件**：OCR 本期为占位实现，扫描版教材导入会提示暂不支持。
5. **并发导入**：大批量知识点导入建议走事务批量插入，避免逐条提交；同名合并需在预览阶段完成冲突确认。
